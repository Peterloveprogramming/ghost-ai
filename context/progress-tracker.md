## Architecture Decisions

- shadcn initialized with the `base-nova` preset and `@base-ui/react` primitives (not Radix) — this was already the state of the repo before this session; kept as-is since `components.json` matched shadcn's own defaults.
- `EditorNavbar` and `ProjectSidebar` are controlled components (sidebar open/closed state, project title, and close/toggle handlers are all props) rather than managing their own state — they're described in 03-editor.md as reusable chrome that later chapters will extend, and the toggle button lives in the navbar while the `isOpen` consumer is the sidebar, so the state has to be owned by whatever future component composes both.
- Auth is enforced at the proxy (`proxy.ts`, `auth.protect()` on all non-public routes) AND `/` re-checks with `await auth()` for its own redirect. Per-route/per-mutation checks in `app/api`, Server Actions, and Liveblocks token issuance are still required (architecture.md invariant 3) — the proxy is not the only gate.
- `@clerk/nextjs` v7 pairs with `@clerk/ui` for themes (not `@clerk/themes`, which is the v6 / Core 2 package). `import { dark } from "@clerk/ui/themes"`.
- Project dialog state is shared via a `ProjectDialogsProvider` React context mounted in `EditorShell`, because the two triggers (editor-home `Plus` button, sidebar rows/footer) live in sibling subtrees (`children` vs `ProjectSidebar`) and must drive the same dialog + form + loading state. The `useProjectDialogs()` hook holds the logic; the provider runs exactly one instance and also renders the three portaled dialogs. Consumers call `useProjectDialogsContext()`.
- The workspace route is `app/editor/[roomId]` (not `[projectId]`): the URL param is the Liveblocks room id, which equals the project id (architecture.md invariant 6). Page-level room access is verified by `lib/project-access.ts` (`getCurrentIdentity` + `findAccessibleProject`), separate from the `app/api` mutation gate (`authorizeProjectMutation` in `lib/projects.ts`) which stays owner-only; page access additionally allows collaborators. `EditorShell` stays a shared client shell for both `/editor` and `/editor/[roomId]` and route-switches its chrome via `useParams()` rather than the layout tree branching.
- 10-share-dialogue.md reused both existing access helpers rather than adding new ones: `findAccessibleProject` (owner-or-collaborator) gates the collaborator-list `GET`, `authorizeProjectMutation` (owner-only) gates invite `POST` and remove `DELETE`. `EditorShell` derives `isOwner` client-side from the same `ownedProjects`/`sharedProjects` props it already uses for `activeProject`, purely to decide which controls to render — the actual invite/remove authorization only happens server-side in the two owner-only routes, so a stale or spoofed client `isOwner` can't grant real access.
